# Local security model

The application is intended for a single trusted workstation. By default it binds to 127.0.0.1 and checks the incoming Host. The container variant must publish to loopback. A randomly generated local credential is provisioned for each account. Runtime comparison uses scrypt and constant-time digest comparison. Passwords in the local sign-in file are private development credentials. File permissions and Windows ACLs inherit protection from the chosen local directory. Keep it outside shared folders. The source package contains no generated sign-in file.

The launcher’s optional one-time browser ticket expires after 90 seconds and is exchanged for a random HttpOnly SameSite=Strict session cookie. The browser removes the ticket fragment from its address. Sessions expire after eight hours and are invalidated by restart or sign-out. POST requires JSON. An Origin, when present, must match the loopback host and port. Local HTTP requires a protected host; deployed TLS, identity federation, secret rotation, multi-process rate limiting and external immutable audit storage are field prerequisites.

The assigned account chooses the tenant database and branch scope. Request data cannot select another database. Owners have chain scope. Managers operate in their assigned branch. Storekeepers record routine stock changes and transfer handling. Managers and owners approve adjustments, counts and orders. The named approver is tied to the session. Viewers and auditors cannot approve stock. The audit role can inspect chain-wide mutation records. A transfer participant sees the route and the constraints needed to handle that movement. Procurement and receipt are entirely local simulation events.

Write requests carry an idempotency key, actor and payload digest. SQLite transactions cover the authorization-dependent operation, result and audit. Audit records store selected business metadata and digests. Raw pilot CSV content is excluded from the generic mutation log. Logs contain method and path, without session cookies or passwords. Parameter binding, DOM escaping, CSP, extension/path checks, quantity and file limits, and formula-safe CSV serialization are implemented.

The pilot parser accepts an exact field allowlist, restricts file size and rejects additional columns. Only coded operational records are within scope. Free text and coded inputs still require custodian review. Seeded tenant IDs cannot receive PILOT_MEASURED. File-based lab identities and local prototype controls have not undergone an independent security or regulatory assessment.
